# 새 워크플로 만들기

rules/09-입력-처리-출력 · rules/10-Agent와-워크플로 를 먼저 읽는다.

## 1. 정하기 (한 번에 묻고, 답이 없으면 기본값)
- 무엇을, 언제(cron), 결과를 어디로(DM·토픽·안 올림), 알릴 것이 없을 때 조용히 할지.
- 이름: 짧은 한글 또는 영문, 띄어쓰기 대신 '-'.

## 2. 입력 길
- 공식 API·MCP 가 있으면 그것. 없을 때만 AI 브라우저(사람이 로그인). 가져오는 법은 이 스킬 문서의 '입력' 절 한 곳에만 적는다.
- 비밀값이 필요하면 스킬 jarvis:infra-ops '비밀값이 새로 필요할 때'.

## 3. 만들기
```
~/jarvis/skills/<이름>/
  SKILL.md         --- name / description(언제 쓰는지, 사용자가 할 말 예시) --- + 절차(판단 단계만)
  scripts/         판단 없는 단계(파이썬 등). 결과는 표준출력, 실패는 0 아닌 끝 코드
  schedule.yaml    예약(홈 schedule.yaml 과 같은 모양, '작업:' 목록)
```
- 스크립트는 상태를 `.harness/state/<이름>.json` 에 두고, 바뀐 것이 있을 때만 출력한다(없으면 아무것도 찍지 않음 = 안 올라감).
- AI 판단이 필요한 예약은 `종류: 지시`, `실행: "스킬 <이름> 을 읽고 그대로 한다."` 한 줄. 긴 지시문을 예약표에 쓰지 않는다.
- 재료 모으기가 오래 걸리면 스크립트로 먼저 모으고 지시는 그 출력만 보게 한다.
- 되돌릴 수 없는 출력(보내기 등)이 있으면 그 단계는 승인 요청으로(스킬 jarvis:approval-request). 새 실행 대상이 필요하면 config-apply.
- 꼭 지켜야 하는 것(이 일은 이 명령으로만 등)은 hooks/gate.json 의 routes 에 더하자고 config-apply 로 올린다.

## 4. 시험
- 스크립트를 임시 상태 파일로 한 번 돌려 본다(`--state /tmp/…` 처럼 실제 상태를 건드리지 않게).
- 지시 예약이면 지금 한 번 같은 지시를 직접 따라 해 본다.
- 처음에는 `상태: 끔` 으로 두고 사용자에게 결과 예시를 보여 준 뒤 켠다(되돌릴 수 있으니 바로 켜도 된다. 켰으면 알린다).

## 5. 남기기
- `jarvis log add "워크플로 <이름> 만듦" --결과 "켬/끔" --근거 "skills/<이름>/"`.
- 예약 시각·끄는 법을 SKILL.md 맨 아래 '운영' 절에 두 줄로.
