# 승인 요청 (실행기)

되돌릴 수 없는 일은 직접 하지 않는다. 요청을 만들면 실행기가 내용을 봉인하고, 대표가 메신저(텔레그램·Slack·Discord)의 버튼으로 승인한 그대로만 한 번 실행한다. 글자 '승인' 은 승인이 아니다.

## 상태 보기
- `jarvis exec pending`(결정 기다림 · 승인됐고 실행 기다림 · 실행 중) · `jarvis exec list` · `jarvis exec show R-3`(`#요청3`·`3` 도 됨) · `jarvis exec targets`.
- "나갔다/기다린다" 를 말하기 전에 반드시 show 로 확인한다.
- 상태: 봉인(승인 대기) → 승인 → 실행 중 → 완료 | 실패 | 불확실 | 실행 안 함. 거부 · 수정 요청은 거기서 끝.
  '수정 요청' 이면 show 의 '대표 수정 요청:' 메모대로 고쳐 새 요청을 낸다. '불확실' 은 다시 하지 않는다(결과를 사람이 확인).

## 요청 내기
1. 대상 고르기: `jarvis exec targets`. 맞는 대상이 없으면 아래 '대상 더하기'.
2. 입력이 필요한 대상이면 입력 파일을 .harness/work/ 아래에 만든다(봉인할 내용 그대로).
3. `jarvis exec request --target 대상 [--input 파일] --if-rejected "거부하면 생기는 일" --결론 "…" --배경 "…" --본문 "…"`
   - 결론(300자): 무엇을 승인하는지, 승인하면 언제 무엇이 일어나는지. 대표 눈에 보이는 말로.
   - 배경(800자): 왜. 대표가 한 말 원문.
   - 본문(1000자): 보이는 변화, 되돌리는 법.
   - 코드·파일 이름은 세 칸에 쓰지 않는다(승인 글 맨 아래 '작업용' 에 봉인된 내용이 저절로 붙는다).
4. 요청 하나에 일 하나. 같은 내용이 이미 기다리면 거절된다(두 번 나가지 않게).
5. 저장소 대상은 작업 폴더가 그 가지에서 깨끗해야 한다(저장 안 된 변경이 있으면 거절). 승인~실행 사이 대상 경로가 바뀌면 실행하지 않는다.
6. 요청 뒤 따로 닫을 것은 없다. 승인·실행·결과는 DM 과 한 일 기록에 저절로 남는다. 기다리는 동안 '멈춤' 으로 보고하지 않는다.

## 대상 더하기·설정 바꾸기 (config-apply)
hooks/(targets.yaml · gate.json · permissions.json)는 직접 고치지 못한다(문지기). 대신:
1. 지금 파일을 읽고 바꾼 전체 내용을 만든다.
2. `.harness/work/config/<이름>.json` 에 `{"file": "targets.yaml", "content": "<새 전체 내용>"}` 로 쓴다.
3. `jarvis exec request --target config-apply --input 그파일 --if-rejected "설정은 그대로" --결론 "실행 대상에 ○○를 더합니다" …`
4. 승인되면 실행기가 옛 파일을 .harness/state/backup/ 에 두고 바꾼다. permissions.json 이면 권한도 다시 만든다.
- 새 대상의 명령은 짧고 정해진 것으로. 매번 다른 명령을 돌리는 '아무거나 실행' 대상은 만들지 않는다(승인의 뜻이 없어진다).

## 하지 않을 것
- 실행기 데몬·보내기 몸통을 직접 부르지 않는다. 멈춤 풀기(`jarvis exec resume`)는 대표 몫.
- 실행기 전체를 급히 멈춰야 하면 `jarvis exec pause`(다시 켜기는 대표).
- 하위 Agent 에게 요청을 내게 하지 않는다(문지기가 막음). 결과를 받아 검토한 뒤 Jarvis 가 낸다.
