# 코드 작업 (맡기고 검토)

쓰는 쪽(맡긴 Agent)과 검토하는 쪽(Jarvis)을 나눈다. 가능하면 다른 모델로 맡긴다.

## 철칙
- 본 작업 폴더(사용자가 쓰는 체크아웃)는 고치지 않는다. 일마다 작업 폴더를 만든다: `~/jarvis/.harness/work/<날짜>-<짧은이름>`.
- 고치기 전에 본 폴더의 `git status`, 최근 커밋 시각(`git log -5 --format="%h %ad %s" --date=iso`), `git worktree list` 를 본다. 누가 고치는 중이면 멈추고 묻는다.
- 새 기능은 꺼 둔 기본값(스위치)으로 넣고, 켜는 것은 사용자가 정한다.
- 운영 DB 에 쓰지 않는다. 비밀값을 파일에 적지 않는다. push 는 hooks/gate.json 의 push_ok 원격만(강제 금지), 운영 반영은 승인으로.
- 맡긴 Agent 의 보고를 그대로 믿지 않는다. 아래 '검토' 를 직접 한다.

## 순서
1. 정하기: 무엇을 왜(사용자가 한 말 원문), 어느 저장소, 배포가 필요한지. 같은 일이 이미 있는지 `git worktree list`·`jarvis exec pending`.
2. 작업 폴더: `git -C <저장소> worktree add ~/jarvis/.harness/work/<이름> -b jarvis/<이름> <기준가지>`.
   무거운 설치 폴더(node_modules 등)는 새로 깔거나 바로가기로 빌린다(커밋하지 않는다). 디스크 여유를 먼저 본다(`df -h ~`).
3. 맡기기: Agent 도구, 앞쪽(foreground)에서 이 턴 안에 받는다. 맡기는 글에 빠짐없이:
   - 목표와 '끝난 상태'. 사용자가 한 말 원문, 이미 알아낸 것·아닌 것으로 확인한 것.
   - 작업 폴더 절대경로와 가지. "이 폴더에서만 고친다. 본 폴더는 읽기만."
   - 고치지 말 것: 본 폴더, 운영 DB, 비밀값 파일, 다른 가지, 스위치 기본값, 목표와 관계없는 정리. 커밋·push·배포·알림 금지.
   - 그대로 돌릴 시험 명령(관련 시험만, 바꾸기 전과 뒤를 비교).
   - 보고할 것: 바꾼 파일과 이유, 시험 명령과 결과(통과·실패·건너뜀, 원래 실패하던 것), 눈에 보이는 변화, 확실하지 않은 것, 되돌리는 법.
   - 고객 실명·대화 원문·비밀값은 넣지 않는다.
4. 검토(Jarvis 가 직접):
   - `git -C <작업폴더> status` · `git -C <작업폴더> diff`: 목표 밖 파일, 스위치 기본값, 비밀값, 내부 정보가 공개 파일에 들어갔는지.
   - 시험을 같은 폴더에서 다시 돌려 보고와 같은지.
   - 눈에 보이는 변화를 한두 줄로 말할 수 있어야 한다. 못 하면 검토가 안 끝난 것.
   - 고칠 점이 있으면 같은 Agent 에 이어서 또는 새로 맡긴다. 세 번 넘게 오가면 멈추고 결론·이견을 정리해 올린다.
5. 커밋(작업 폴더에서, 저장소 관례대로 메시지). push 는 위 철칙대로.
6. 배포가 필요하면 스킬 jarvis:approval-request(저장소 대상, 작업 폴더가 그 대상의 가지·경로와 맞아야 함).
7. `jarvis log add "무엇을" --결과 "…" --근거 "작업폴더·커밋·R-n"`. 못 끝낸 것은 스킬 jarvis:todo 에.
8. 보고: 무엇이 바뀌는지(사용자 눈으로) → 시험 결과 → 승인·배포 상태(#요청n) → 되돌리는 법.

## 턴 안에서 끝낸다
- DM 세션은 답을 올리면 끝나서 뒤에서 돌던 Agent·명령도 같이 끝난다. 백그라운드로 맡겨 놓고 답을 먼저 올리지 않는다.
- 큰 일은 쪼갠다(원인 찾기 → 고치기 → 시험 더하기). 단계마다 커밋해 두면 다음 턴이 이어받는다.

## 작업 폴더 치우기
- 가지가 합쳐졌거나 버린 일이면 `git -C <저장소> worktree remove <작업폴더>`(강제 없이). 저장 안 된 파일이 있으면 거절되니 보고 정한다.
  가지·커밋은 남아 다시 꺼낼 수 있다. 저녁 요약 재료의 '치울 만한 작업 폴더' 칸을 보고 치운다.
