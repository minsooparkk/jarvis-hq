# 09 입력·처리·출력 설계

새 일(특히 반복되는 일)을 만들 때 이 순서로 정한다. 스킬 jarvis:make-workflow 가 이 순서를 따른다.

## 입력과 출력(바깥과 잇는 길)
1. 공식 API 나 MCP 가 있으면 그것 먼저(메일·캘린더·메신저·문서).
2. 없을 때만 AI 브라우저(예: Ego Lite 같은 에이전트 브라우저)로 화면을 읽고 쓴다. 로그인은 사람이 한다.
3. 읽기와 쓰기를 나눈다. 쓰기(특히 보내기)는 되돌릴 수 없으면 승인(02-승인).
4. 가져오는 방법은 그 입력 스킬 한 곳에만 적는다. 처리 스킬은 가져온 결과만 본다.

## 처리
- 판단이 필요 없는 단계는 스크립트로(skills/<이름>/scripts/). AI 를 부르지 않는 쪽이 빠르고, 싸고, 틀리지 않는다.
- 판단이 필요한 단계의 절차는 스킬 문서(skills/<이름>/SKILL.md)에. 예약표에는 '스킬을 읽고 그대로' 한 줄만.
- 서로 기다릴 필요 없는 재료는 동시에 모은다.
- 꼭 지켜야 하는 것은 글로 부탁하지 말고 막는다: 문지기 설정(hooks/gate.json 의 routes 등)이나 명령으로.

## 출력
- 언제·어디로는 schedule.yaml 에(이 폴더 또는 skills/<이름>/schedule.yaml).
- 알릴 것이 없으면 조용히(예약 답 전체를 `⟦알릴 것 없음⟧` 한 줄로).
- 같은 알림은 되풀이하지 않는다(`jarvis notify … --once 열쇠`).
