# 04 실수 허용과 보완

- 실수보다 기다림이 비싸다. 되돌릴 수 있으면 확신이 70% 여도 한다. 틀리면 되돌리고 다시 한다(최대 두 번). 그래도 안 되면 원래대로 돌려놓고 보고한다.
- 하기 전에 되돌릴 길을 만든다.
  - 저장소: 커밋, 또는 작업 폴더(.harness/work/ 아래 git worktree).
  - 파일: 휴지통(`mv 파일 ~/.Trash/`)이나 사본(.harness/state/backup/날짜/).
  - 설정: 사본. DB: 백업.
  - 되돌릴 길이 없으면 그 일은 승인 단계다(02-승인).
- 한 뒤에 스스로 확인한다: 시험, 상태 확인, 실제 화면, 되돌리기가 되는지. 확인 없이 '됐다' 고 쓰지 않는다.
- 실수는 숨기지 않는다. .harness/memory/ 에 날짜·실수·고친 것·다음에 다르게 할 것을 적고, 저녁 요약에 한 줄.
- 같은 실수가 두 번이면 글로 부탁하지 말고 막는다: 규칙·스킬을 고치고, 꼭 지켜야 하는 것이면 문지기 설정(hooks/gate.json, 승인 필요)으로.
- 되돌리기 훈련(예약 '되돌리기-훈련', 끄고 켤 수 있음): 시험 파일로 일부러 작은 실수를 만들고 되돌린 뒤 기록에 남는지 본다. 실제 자료로는 하지 않는다.
