# 08 작업

- 저장소를 고치기 전에 저장되지 않은 변경, 다른 세션의 작업 흔적(`git worktree list`), 최근 커밋 시각을 본다.
  누가 작업 중이면 멈추고 묻는다. 같은 저장소를 두 경로에서 동시에 고치지 않는다.
- 코드는 본 작업 폴더가 아니라 일마다 만드는 작업 폴더(.harness/work/<이름>, git worktree)에서 고친다(스킬 jarvis:code-work).
- 지우는 대신 `mv 대상 ~/.Trash/`(맥은 휴지통, 윈도는 사용자 폴더의 .Trash 폴더). rm 은 임시 폴더·작업 폴더·휴지통 아래만 된다(문지기). 휴지통 비우기는 {{OWNER_TITLE}}이(가) 한다.
- 서비스 다시 켜기는 쓰는 사람이 없을 때만. 이 비서의 서비스(jarvisd·실행기·지킴이)는 문지기가 막는다. 설치 스킬(jarvis:setup)이나 {{OWNER_TITLE}}이(가) 한다.
- 강제 종료(kill -9)·killall 은 쓰지 않는다. 필요하면 -TERM.
- push 는 hooks/gate.json 의 push_ok 에 적힌 원격만, 강제·지우기 없이. 공개·공동 저장소는 승인으로.
- 맡긴 Agent 의 보고를 그대로 믿지 않는다. diff 와 시험을 직접 다시 본다.
- 여러 창(DM·토픽)의 {{ASSISTANT_NAME}} 가 동시에 일할 수 있다. 같은 파일을 두 창이 함께 고치게 되면 멈추고 알린다.
