# 구조

## 세 자리
| 자리 | 무엇 | 누가 바꾸나 |
|---|---|---|
| 플러그인(Claude Code 캐시) | 스킬(`jarvis:…`), 훅(문지기·세션 시작), 홈 템플릿, 엔진 원본, 설치 스크립트 | 플러그인 업데이트 |
| 엔진 `~/.jarvis-hq` | 데몬이 실제로 쓰는 코드 사본·venv·설정·명령 | `/jarvis:setup` 이 플러그인에서 복사 |
| 홈 `~/jarvis` | 규칙·내 스킬·문지기 설정·예약·기록 | 사용자와 Jarvis |

플러그인 캐시 자리는 판마다 바뀌어서, 서비스로 오래 도는 데몬은 거기서 돌지 않고 엔진 자리 사본으로 돈다.
`/jarvis:setup` 을 다시 돌리면 엔진 사본만 새 판으로 바뀐다(옛 판은 `~/.jarvis-hq/backup/`).

## 프로그램(AI 가 아님)
| 이름 | 서비스 이름(맥 launchd 라벨 · 윈도 작업 이름) | 하는 일 |
|---|---|---|
| jarvisd | com.jarvis-hq.jarvisd | 메신저(텔레그램·Slack·Discord) 받기·보내기, Claude Code 세션 띄우기(진행 표시·말 합치기), 승인 버튼, 보낼 글 대기열, 예약 |
| 실행기 | com.jarvis-hq.executor | 승인·서명된 요청만, 봉인을 다시 맞춰 본 뒤 한 번 실행 |
| 지킴이 | com.jarvis-hq.watchdog | 5분마다 데몬이 살아 있는지(심장박동) 보고 다시 띄움, DM 알림 |
| 문지기 | (훅) | Claude 가 도구를 쓰기 직전에 되돌릴 수 없는 명령·비밀값·실행기 입구를 막음 |
| jarvis 명령 | | `jarvis exec · log · notify · perms · secret · messenger(예전 이름 telegram) · status · brief · stt · mail` |

## 운영체제마다 다른 것 (엔진 jhq/platform)
| | 맥 | 윈도 |
|---|---|---|
| 서비스 | launchd(~/Library/LaunchAgents) | 작업 스케줄러(로그온 때 시작 + 5분마다 지킴이, 관리자 권한 없음). 창 없는 pythonw 가 엔진의 winlaunch.py 를 거쳐 돈다 |
| 금고 | 키체인(`security`) | 자격 증명 관리자(일반 자격 증명, ctypes) |
| 명령 | ~/.local/bin/jarvis → 엔진 bin/jarvis | ~/.local/bin 의 jarvis.cmd(PowerShell·cmd)와 jarvis(Git Bash) |
| .claude/skills | 심볼릭 링크 | 디렉터리 정션 |
| 셸(실행 대상·예약 스크립트) | /bin/bash | Git Bash |
| 휴지통 | ~/.Trash | 사용자 폴더의 .Trash 폴더 |
| 문지기 훅 | 맥 기본 python3 | Git Bash 의 sh 가 py·python 을 찾아 돎(홈 settings.json 은 엔진 python.exe 실행 형식) |
문지기·세션 시작 훅은 엔진을 부를 수 없는 혼자 도는 스크립트라 OS 를 스스로 본다. 그 밖의 코드는 sys.platform 을 보지 않는다.

## 대화가 도는 길
1. 메신저 → jarvisd(받기: 텔레그램 긴 기다림 · Slack Socket Mode · Discord 게이트웨이, 엔진 jhq/messengers). 대표가 DM(텔레그램은 설정한 그룹도)에서 보낸 것만 받는다.
2. jarvisd 가 홈에서 `claude -p … --output-format stream-json` 을 띄운다. DM 은 하루 한 대화(같은 날은 이어 감),
   그룹 토픽은 토픽마다 한 대화. Claude 에게는 메신저 토큰·서명 열쇠를 넘기지 않는다.
3. Claude 가 도구 사이에 쓴 짧은 글은 그때그때 따로 올라가고, 20초 동안 말이 없으면 '…중이에요. 잠시만요.' 한 줄이 간다.
4. 답을 만드는 동안 온 말은 '말씀 받았습니다' 뒤 지금 답에 합쳐 하나로 올린다.
5. Claude 가 알릴 것(그림·파일 포함)은 `jarvis notify` 로 대기열에 넣고 jarvisd 가 올린다.

## 예약
`~/jarvis/schedule.yaml` 과 `~/jarvis/skills/<이름>/schedule.yaml`. 종류는 셋: 지시(Claude 가 스킬을 읽고 한다),
스크립트(프로그램만, 바뀐 것이 있을 때만 출력), 승인묶음(결정 안 한 승인 다시 알림). 매분 다시 읽으니 고친 뒤 다시 켤 필요가 없다.
같은 예약이 계속 실패하면 6시간에 한 번만 알린다.

## .harness

| log/ | 한 일 기록(날짜별, 더하기만) |

| state/ | 데몬 상태·심장박동·로그·설정 사본 |
| work/ | 작업 폴더(코드 worktree·받아쓰기 결과·메일 초안) |
| inbox/ | 메신저로 받은 파일 |

## 규칙이 늘 걸리는 법
- 홈의 `CLAUDE.md` 가 세션 시작 때 `rules/00·01·02·07` 과 `RULES.md`(색인)를 불러온다. 나머지 규칙은 색인을 보고 그때 읽는다.
- 플러그인의 SessionStart 훅이 홈에서 연 세션에만 지금 시각·승인 대기 수·오늘 기록 수를 붙인다. CLAUDE.md 가 없어졌으면 핵심 규칙을 대신 넣는다.
- 꼭 지켜야 하는 것은 글이 아니라 문지기(훅)와 권한(settings.json)이 막는다.
