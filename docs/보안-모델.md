# 보안 모델

## 무엇을 지키나
1. 되돌릴 수 없는 일(보내기·배포·결제·영구 삭제·공개 게시)은 대표가 본 그대로만, 한 번만.
2. 비밀값(봇 토큰, 서명 열쇠, API 키) 원문이 대화·기록·파일·메시지에 남지 않게.
3. 대표 말고 다른 사람이 봇을 부리지 못하게.
4. 이 비서의 울타리(문지기 설정, 실행 대상, 장부)를 Agent 가 스스로 넓히지 못하게.

## 무엇으로 지키나
| 장치 | 막는 것 |
|---|---|
| 금고(맥 키체인·윈도 자격 증명 관리자) | 비밀값은 금고에만. 엔진이 필요할 때 꺼내 쓰고 환경변수·파일에 두지 않는다. Claude 세션 환경에서도 뺀다 |
| 승인 서명 | 승인은 금고의 서명 열쇠로 HMAC 서명. Claude 세션에는 열쇠가 없어 서명을 만들 수 없다 |
| 봉인 | 실행 내용(대상 설정·입력 사본·커밋)의 해시. 승인 화면·승인 순간·실행 직전 세 번 맞춰 본다 |
| 받기 거르기 | 텔레그램은 설정한 대표 chat id 가 DM 이나 설정한 그룹에서 보낸 글·버튼만(다른 방에 초대되면 나온다). Slack 은 대표 멤버 ID 가 앱과의 DM 에서(팀 id 를 적어 두면 다른 워크스페이스 것도 버림), Discord 는 대표 사용자 ID 가 봇과의 DM 에서 보낸 것만(서버 글은 버림) |
| 문지기(PreToolUse 훅) | 금고 읽기, 비밀 파일 열기, rm(임시·작업 폴더·휴지통 밖), 강제 push·허락 안 한 원격 push, 보호 DB 쓰기, 서비스 내리기, kill -9, 배포·공개 명령, 보내기 MCP 도구, 실행기 입구, hooks/·장부 쓰기, 하위 Agent 의 요청·알림 |
| 권한(settings.json) | 잠금 거부(.env·~/.ssh·금고 읽기, 강제 push, 비밀값 넣기, 실행기 다시 켜기, 메일·메시지 보내기 도구). 풀려면 대표 승인 문구가 필요(Claude Code) |
| 샌드박스(Codex) | 쓰기는 홈·임시 폴더(와 permissions.json 의 additionalDirectories)만, 네트워크 기본 꺼짐, 샌드박스 밖으로 나가는 요청은 묻지 않고 거절(승인 정책 never) |
| 지우지 않기 | 지우는 대신 휴지통. 엔진 옛 판·설정 옛 판은 사본으로 남긴다 |

## 한계 (꼭 알아 둘 것)
- 문지기와 권한은 실수 방지 울타리이지 완전한 보안 경계가 아니다. Claude·Codex 세션은 사용자와 같은 계정 권한으로 돈다.
  작정하고 우회하는 프로그램(예: 금고를 읽는 코드를 새로 짜서 돌리기)을 모두 막을 수는 없다. 그래서 규칙(rules/07)도 '막히면 다른 길을 찾지 않는다' 고 적는다.
- 문지기가 고장 나면(오류) 막지 않고 통과시킨다(일이 멈추지 않게). 고장 난 것은 stderr 에 남는다.
- 메신저 계정을 빼앗기면 승인 버튼도 빼앗긴다. 쓰는 메신저(텔레그램·Slack·Discord)의 2단계 인증을 켜 둔다.
- 봇 토큰이 새면 바꾸고 다시 넣는다: 텔레그램 BotFather `/revoke` → `jarvis secret set telegram`, Slack 앱 설정에서 토큰 다시 발급 →
  `jarvis secret set slack-bot`·`slack-app`, Discord 개발자 포털 Reset Token → `jarvis secret set discord`.
- Slack 워크스페이스 관리자는 그 워크스페이스의 앱과 DM 을 볼 수 있는 경우가 있다(회사 워크스페이스면 특히). 비밀 이야기는 텔레그램·Discord 가 낫다.
- Discord 는 봇이 대표와 같은 서버에 있어야 DM 을 보낼 수 있다. 그 서버에 다른 사람을 들이지 않는다(봇의 Public Bot 은 끈다).
- 브라우저로 보내는 예시 스킬(browser-send)은 실행기 대신 대화 안 확인으로 승인을 받는다. 가능하면 실행 대상으로 바꿔 쓴다.
- 문지기는 기본으로 Jarvis 홈에서 연 세션과 jarvisd 가 띄운 세션에만 건다(다른 작업을 방해하지 않게). 단 비밀값 넣기·실행기 입구·
  hooks/·장부 쓰기는 어디서 연 세션이든 막는다. 모든 세션에 걸려면 hooks/gate.json 의 scope 를 all 로.

## Codex 로 돌 때 (Claude Code 와 다른 점)
`jarvis agent status` 가 같은 표를 보여 준다. 실제로 돌려 본 것과 못 해 본 것은 docs/codex-확인할-것.md.
| 항목 | Claude 대비 | 설명 |
|---|---|---|
| 셸 명령·파일 고치기(apply_patch)·MCP 도구 | 같음 | 같은 gate.py 가 PreToolUse 훅으로 본다. Codex 의 코드 모드(exec) 안 명령에도 걸린다(실제로 확인). apply_patch 의 'Delete File' 은 rm 규칙 |
| 권한 잠금 거부 | 약함 | Codex 에는 세션마다 줄 수 있는 같은 장치가 없다. 같은 항목은 문지기가 막는다. permissions.json 의 allow·deny 는 쓰이지 않는다 |
| 하위 Agent 제한 | 약함 | 하위 Agent 표시가 훅에 오는지 확인 못 해 주 Agent 규칙으로 본다(push·승인 요청 제한이 안 걸림. 승인 요청은 그래도 대표 버튼이 있어야 실행) |
| 이미 띄운 셸에 넣는 글(write_stdin) | 확인 못 함 | Codex 문서는 '다시 보지 않는다' 고 적는다. 문지기가 write_stdin 도구를 셸 명령처럼 보게 걸었지만 훅이 실제로 불리는지 확인 못 했다. 샌드박스(쓰기 자리·네트워크)는 그대로 걸린다 |
| 샌드박스 | 강함(네트워크 꺼짐일 때) | 셸로 보내기·배포·push 가 나가지 못한다. `--network on` 이면 Claude 와 같다 |
| ChatGPT 앱(연결)·브라우저·컴퓨터 사용 | 꺼 둠 | 훅이 거는지 확인 못 해 데몬 세션에서 끈다. 켜려면 config.json 의 codex.apps(확인한 뒤에만) |
| 문지기 신뢰 | 다름 | 데몬·`jarvis agent open` 세션은 `--dangerously-bypass-hook-trust` 로 문지기를 늘 돌린다. 이때 사용자 Codex 설정에 있는 다른 훅도 검토 없이 돈다. 그냥 연 Codex 에서는 /hooks 에서 신뢰해야 플러그인 문지기가 돈다 |
| 에이전트 바꾸기 | 같음 | `jarvis agent set` 은 문지기가 막는다(대표가 자기 터미널에서) |

## 비밀값 다루기
- 넣기: 사용자가 자기 터미널에서 `jarvis secret set 이름`(입력이 화면에 안 보임, 표준입력으로 금고에). 대화창에 붙여 넣지 않는다.
- 보기: `jarvis secret list`(있는지만).
- 지우기: 사용자 터미널에서 `jarvis secret delete 이름`, 또는 `/jarvis:uninstall` 에서 물어본 뒤.
- 금고 항목 이름: `jarvis-hq.<이름>`, 계정 `jarvis-hq`(맥 키체인과 윈도 자격 증명 관리자 모두).
- 윈도 자격 증명 관리자의 값은 같은 윈도 사용자로 도는 프로그램이면 읽을 수 있다(맥 키체인처럼 프로그램마다 묻는 창이 없다).
  그래서 윈도에서는 문지기의 금고 읽기 막기(cmdkey, 금고 이름이 든 파이썬 코드 등)가 맥보다 더 중요하다.
- 윈도 문지기는 Bash(Git Bash) 명령을 기준으로 만들었다. PowerShell 도구를 켜면 지우기·서비스 멈추기·금고 읽기·울타리 쓰기 꼴만 넓게 막는다.
