# 윈도우에서 확인할 것 (실제 기기 점검표)

Windows 지원 코드는 맥에서 만들었다. 맥에서는 가짜 실행기·가짜 금고로 '어떤 명령과 파일을 만드는지'만 시험했고
(tests/test_platform.py, tests/test_gate.py), **윈도에서 실제로 돌려 본 것은 하나도 없다.** 아래를 실제 Windows 10/11 에서
차례로 해 보고 칸을 채운다. 안 되는 것이 나오면 고칠 곳(파일)도 적어 두었다.

준비: Windows 11(또는 10 22H2), 관리자가 아닌 보통 사용자 계정 하나. 사용자 이름에 한글이나 띄어쓰기가 있는 계정으로 한 번 더 하면 좋다.
Git for Windows, python.org 의 Python 3.11 이상(설치할 때 'py launcher' 켬), Claude Code 네이티브 설치(claude.exe).

## 1. 설치
| # | 해 볼 것 | 기대 | 결과 |
|---|---|---|---|
| 1 | Claude Code 에서 `/plugin marketplace add …` → `/plugin install jarvis@jarvis-hq` | 스킬·훅이 보인다 | |
| 2 | `/jarvis:setup` 이 `py "<플러그인>/scripts/install.py" --doctor --json` 을 돌림 | JSON 이 나오고 한글이 깨지지 않는다 | |
| 3 | 설치(`--dry-run` 없이) | `~\.jarvis-hq\venv\Scripts\python.exe` 생김, PyYAML·tzdata 받음 | |
| 4 | 시간대 | config.json 의 timezone 이 `tzutil /g` 에 맞는 IANA 이름(한국이면 Asia/Seoul). 표에 없는 시간대면 `timezone_unknown` 으로 묻는다 | |
| 5 | `~\jarvis\.claude\skills` | `~\jarvis\skills` 를 가리키는 디렉터리 정션(`dir /AL` 에 JUNCTION). 관리자 권한을 묻지 않는다 | |
| 6 | 명령 바로가기 | `~\.local\bin\jarvis.cmd`(PowerShell·cmd)와 `~\.local\bin\jarvis`(Git Bash). 새 PowerShell 창에서 `jarvis version` | |
| 7 | 홈 settings.json 의 문지기 훅 | `"command": "...\venv\Scripts\python.exe", "args": ["...\engine\hooks\gate.py"]` 실행 형식 | |

## 2. 비밀값(자격 증명 관리자)
| # | 해 볼 것 | 기대 | 결과 |

| 2 | Git Bash(mintty)에서 같은 명령 | 파이썬이 터미널이 아니라고 보고 거절할 수 있다(mintty 는 진짜 콘솔이 아님). 그러면 안내문을 'PowerShell 에서' 로 고친다 | |
| 3 | '자격 증명 관리자' 창 → Windows 자격 증명 → 일반 자격 증명 | `jarvis-hq.telegram-bot-token`, `jarvis-hq.seal-key` 가 보인다(값은 안 보임) | |

## 3. 서비스(작업 스케줄러)
| # | 해 볼 것 | 기대 | 결과 |
|---|---|---|---|
| 1 | 토큰·대표 id 를 넣고 설치 다시 | `schtasks /Create /XML …` 셋이 관리자 권한 없이 된다(작업 이름 `com.jarvis-hq.jarvisd` 등, 루트 폴더) | |
| 2 | '작업 스케줄러' 앱 | 세 작업이 보이고, jarvisd·executor 는 '실행 중', 실행 시간 제한 없음 | |
| 3 | 콘솔 창 | 어떤 창도 뜨지 않는다(pythonw.exe, 하위 claude·bash 도 CREATE_NO_WINDOW) | |
| 4 | 로그 | `~\jarvis\.harness\state\logs\jarvisd.log` 에 한글이 깨지지 않고 쌓인다 | |
| 5 | 로그아웃 → 로그인 | jarvisd·executor 가 다시 뜬다(로그온 트리거) | |
| 6 | 작업 관리자에서 jarvisd 의 pythonw.exe 끝내기 | 1분 안(RestartOnFailure) 또는 5분 안(지킴이)에 다시 뜨고 DM 알림 | |
| 7 | 지킴이 | 5분마다 돈다(TimeTrigger 반복, Duration 없음 = 끝없이). `watchdog.log` 에 '정상' | |
| 8 | `Get-ScheduledTask` 상태 읽기 | 한국어 Windows 에서도 상태 이름이 영어(Running·Ready)로 온다 | |
| 9 | 노트북 배터리 | 배터리로 바꿔도 멈추지 않는다 | |
| 10 | 절전에서 깨어난 뒤 | 심장박동이 멈췄으면 지킴이가 다시 띄운다 | |

## 확인 못 한 것(설계 때 추측한 것)
- 작업 정의 XML 의 Settings 칸 순서를 Windows 가 그대로 받는지(내보낸 작업의 순서를 따랐다).
- RestartOnFailure 가 프로그램이 오류로 끝났을 때도 다시 띄우는지(시작 실패에만 먹는다는 말이 있다. 그래서 지킴이가 따로 본다).
- 보통 사용자가 루트 폴더에 작업을 만들 수 있는지(회사 정책으로 막힌 기기는 안 된다).
- Git Bash 에서 확장자 없는 `jarvis`(sh) 파일이 실행되는지, PowerShell·cmd 가 그 파일을 무시하고 `jarvis.cmd` 를 고르는지.
- `chcp` 를 쓰지 않은 jarvis.cmd 가 한글 인자(`--결론 "…"`)를 그대로 넘기는지.
- 받아쓰기 선택 모듈(stt)은 맥(brew) 기준으로만 안내돼 있다. 윈도에서는 ffmpeg·whisper-cli 를 PATH 에 두면 될 것으로 보지만 해 보지 않았다.
