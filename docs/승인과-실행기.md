# 승인과 실행기

되돌릴 수 없는 일은 Jarvis(Claude)가 직접 하지 않는다. 요청을 만들고, 대표가 메신저(텔레그램·Slack·Discord)의 버튼으로 승인하면 실행기가 한 번만 한다.

## 흐름
```
Jarvis ── jarvis exec request ──▶ 장부(executor.db)  상태: 봉인
                                     │ 봉인 = sha256(대상의 실행 방법 전체 + 입력 사본 해시 + 저장소면 커밋의 파일 해시)
jarvisd ── 승인 글 + 버튼 ─────────▶ 대표 DM          (미리보기는 Agent 설명이 아니라 봉인된 내용에서 만든다)
대표 ── 승인 ──▶ jarvisd: 화면의 봉인 = 저장된 봉인 = 지금 다시 계산한 봉인 이면 서명(HMAC, 금고의 seal-key)   상태: 승인
실행기 ── 30초마다: 서명 확인 → 창(시간) 확인 → 봉인 다시 계산 → (저장소면 작업 폴더가 그 커밋과 같은지)
        → 시도 표시 파일을 O_EXCL 로 만들고 상태 '실행 중' 을 먼저 적음 → 실행 → 완료 | 실패 | 불확실
결과 ──▶ 대표 DM(실패는 '긴급' 토픽이 있으면 거기)과 한 일 기록
```

## 메신저마다 같은 것
- 버튼에는 순번(b:0·b:1·b:2)만 싣는다(텔레그램 callback_data · Slack 버튼 value·action_id · Discord custom_id). 무엇을 승인하는지('R-n|봉인')는
  장부(outbox.db 의 posts)에서 그 글 번호로 찾는다. 그래서 버튼 값을 꾸며도 다른 요청을 승인할 수 없다.
- 누른 사람이 설정한 대표 계정이고, 대표 DM(텔레그램은 설정한 그룹도)에서 눌렀을 때만 결정으로 친다. 그 밖은 버리거나(Slack) '권한이 없습니다'
  만 그 사람에게 알린다(텔레그램·Discord).
- 대표가 글자로 '승인' 이라고 써도 승인이 아니다(결정 안 한 승인 목록을 다시 보여 줄 뿐).
- 봉인을 다시 계산해 맞춰 보고 서명하는 것은 메신저 코드가 아니라 실행기 코드(jhq.executor.decide)다.

## 한 번만
- 같은 봉인의 요청이 기다리는 중이면 새 요청을 만들지 않는다.
- 결정은 '봉인' 상태일 때만 바뀐다(두 번 누르거나 DM·토픽 두 글에서 눌러도 한 번). 결정 뒤 버튼은 거둔다.
- 실행 전에 시도 표시 파일을 만든다. 실행기가 도중에 죽어 다시 떠도, 표시가 있거나 '실행 중' 으로 남은 요청은 다시 하지 않고 '불확실' 로 알린다.
- 실패해도 저절로 다시 하지 않는다. 다시 하려면 새 요청과 새 승인.

## 실행하지 않는 경우(실행 안 함)
- 승인 화면에 보였던 봉인과 저장된 봉인이 다를 때
- 승인 순간이나 실행 직전에 다시 계산한 봉인이 다를 때(대상 설정이 바뀜, 입력 사본이 바뀜, 커밋 내용이 바뀜)
- 서명이 없거나 맞지 않을 때
- 저장소 대상의 작업 폴더가 다른 가지이거나, 저장 안 된 변경이 있거나, 대상 경로가 봉인한 커밋과 다를 때

## 실행 대상 (hooks/targets.yaml)
- 여기 적힌 대상만 실행한다. 칸: 이름·실행(명령 목록)·확인·창(always 또는 "05-07")·입력(없음/선택/필수)·저장소·브랜치·경로·시간제한.
- 입력이 있는 대상은 요청 때 파일 사본을 장부에 떠서(읽기 전용) 봉인하고, 실행 때 그 사본 경로를 `$JARVIS_PAYLOAD` 로 넘긴다.
- 기본 대상: `hello`(시험), `config-apply`(hooks/ 설정 바꾸기). 선택: `gmail-send`(Gmail 보내기), 저장소 배포 예시.
- 대상의 내용 전체가 봉인에 들어간다. 대상 명령을 고치면 기다리던 그 대상의 요청은 실행되지 않는다(새로 승인).
- 대상은 정해진 일을 하는 짧은 명령으로 만든다. '아무 명령이나 실행' 대상은 만들지 않는다(승인 글이 무엇을 하는지 보여 주지 못한다).

## 설정 바꾸기도 승인으로
hooks/ 의 gate.json · targets.yaml · permissions.json 은 Jarvis 가 직접 고치지 못한다(문지기). Jarvis 는 새 내용을 만들어
`config-apply` 대상으로 요청하고, 승인되면 실행기가 옛 파일을 `.harness/state/backup/` 에 두고 바꾼다. 사용자는 편집기로 직접 고쳐도 된다.

## 쓰는 명령
`jarvis exec request · pending · list · show R-n · targets · pause` (다시 켜기 `resume` 은 사용자 터미널에서만)
